API Support Casebook

Five support tickets against an insurance-data API, each worked end to end: read the logs, find the root cause, unblock the customer, ship a fix with a regression test, and write the reply. The API, the customer's integration and the logs are real code you can run.

Why this exists

After a final-round interview for a customer success engineering role, the feedback was specific: I needed more hands-on API support experience. So I built the practice ground myself. Northwind is a mock insurance-data API with the behavior real tickets depend on: single-use authorization codes, environment-scoped keys, rate limits with Retry-After, signed webhooks, and a request ID on every log line. Contoso Rentals is a customer whose integration has five realistic bugs.

How each ticket is worked

  1. AcknowledgeReply fast, say what happens next.
  2. Size itSeverity from impact, not volume.
  3. Scope itOne customer or everyone? Since when?
  4. Read the logsRequest IDs, client, endpoint, status, timing.
  5. UnblockGet the customer working before the root cause.
  6. Fix and prove itA change plus a test that fails on the old code.
  7. Close twiceA clear reply, and a note that prevents the next one.
